# 문체·표기·용어 안내

기존 README·기획서·양식 답안에서 뽑은 규칙이다. 새 문서도 같은 목소리로 쓴다.

## 문체

- 설명 문서는 평서문 `~다`로 쓴다. 데모 대본의 "말" 열과 심사 예상 질문의 "말로 하는 답"만 `~습니다`를 쓴다.
- 한 문장에 한 주장. 짧게 쓴다. 표가 문장보다 빠르면 표로 쓴다.
- 과장하지 않는다. "혁신적", "획기적", "완벽한" 같은 수식어를 쓰지 않는다. 조사로 확인하지 못한 것은 "없다"가 아니라 "찾지 못했다"고 쓴다.
- 한계는 숨기지 않고 먼저 말한다. "정직하게" 같은 머리말은 기존 문서에 있으면 유지한다.
- 이모지를 쓰지 않는다. 상태 표시는 글자(적용·미적용·조항 없음)로 쓴다.

## 숫자 표기

| 대상 | 표기 | 예 |
| --- | --- | --- |
| 금액(문서) | 원 단위, 천 단위 쉼표 | 12,834,000원 |
| 금액(말·대본) | 만 원 단위 | 1,283만 원, 300만 원 |
| 비율 | 소수 첫째 자리 | 76.7%, 95.3% |
| 범위 | 물결표 | 58~77%, 95.3~96.2% |
| 승률 | 승/전체 | 30/30, 90/90 |
| 사건 기준 시각 | `+` 시간 | +15.9시간 |
| 시한(표 안) | `h` | 12h 이내 |
| 측정·목표 | 표의 출처 열이나 문장에 "측정", "목표"를 밝힌다 | |

출처는 숫자 옆 괄호나 표의 출처 열에 백틱 경로로 적는다. 예: (`eval/results/robustness.md`)

## 용어집

| 쓴다 | 쓰지 않는다 | 뜻 |
| --- | --- | --- |
| 배상 노출액(한계 배상액) | 페널티 노출액, 페널티 | 한 사이클 더 보류할 때 추가로 발생하는 배상금 |
| 배상 노출 순 | 페널티 순, 노출액 순위 정책 | ClauseTower 배차 정책. 배상 노출액을 트럭 점유 시간으로 나눈 값이 큰 화물부터 |
| 배상 노출 순(절대값) | | 위 값을 시간으로 나누지 않은 변형 |
| 마감 임박 순(기존) | 마감순, 데드라인 순 | 기존 관행 정책 |
| 도착 순, 고액 화물 순 | FIFO, 가액순 | 비교 정책 |
| 탐색 근사 최적(참고) | 최적해 | 우선순위 지역 탐색으로 찾은 상한선. 진짜 최적이 아니다 |
| 배상금 | 페널티 금액 | 지연으로 발생한 금액. 가온헬스케어의 건당 정액만 "위약금"이라고 부를 수 있다 |
| 면책, 불가항력 사유 | 면제 | 계약의 불가항력 조항에 따른 배상 면제 |

| 정답지 | 골든, golden(본문) | 팀이 작성한 계약 조건·판단 기준값. 경로 `contracts/golden/`은 그대로 쓴다 |
| mock 모드 / 실제 모드, 실제 모델 | 가짜 모드 | 정답지 사용 / 실제 LLM 호출 |
| 조치 보드 | 액션 패널 | 우선 배차 대상, 통지 현황, 성립시킬 면책 |
| 계약 케이스(카드·비교표) | 고객 보드 | 고객별 계약 조건 격자 |
| 계약 상세 서랍(항목별·전문 탭) | 사이드 패널 | 조항·원문 인용·판단 체크리스트 |
| 배차 간트, 누적 배상금 곡선 | | 화면 이름 |
| 로컬 도우미 | 로컬 서버, 프록시 | `python -m clausetower serve` |

**고객(가상):** A 한빛전자, B 두루물산, C 세움건설, D 미래식품, E 가온헬스케어, F 바로유통, G 누리에너지, H 청람제약.
**시나리오:** 태풍 상륙(`typhoon`), 항만 적체(`port_congestion`), 자사 WMS 장애(`wms_outage`).
**심사 기준(README 11절):** AI 활용 수준, 문제 해결 방식, 실제 업무 적용 가능성, 재현성.

## 형식

- 제목은 `#` 하나, 절은 번호를 붙인 `##`(예: `## 1. 왜 만들었나`). 기존 문서의 번호 체계를 유지한다.
- 코드·경로·명령·환경 변수는 백틱. 명령 블록은 `bash`로 쓰고, Windows가 다르면 PowerShell 블록을 따로 둔다.
- 링크는 저장소 기준 상대 경로. `docs/` 안의 문서끼리는 같은 폴더 상대 경로(`setup-guide.md`), README에서는 `docs/setup-guide.md`.
- 그림: 새 문서의 구조도는 GitHub가 렌더링하는 Mermaid를 써도 된다. 기존 ASCII 도식은 바꾸지 않는다. 스크린샷은 `docs/screenshots/` 아래 기존 파일만 참조한다.
- 실제 회사·실존 인물·사내 시스템 이름을 쓰지 않는다. 사내 주소 예시는 `https://llm.company.local/v1`처럼 가상 도메인을 쓴다.
