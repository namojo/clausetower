# ClauseTower 해커톤 2일 구현 계획

> 팀원이 해커톤 전날과 당일에 읽는 실행 계획이다. 목표 기능은 [양식 답안](ax-hackathon-form.md) 3번과 같은 네 가지이고, 역할 이름은 [기획서](proposal.md) 10절을 따른다. 숫자의 출처는 품질 게이트 재측정(2026-11-02, README 6절과 같은 값)과 `eval/results/real/run.log`다.
>
> 이 계획은 **제안**이다. 시각·시간·완료 기준은 팀이 첫날 아침에 고쳐 확정한다. 아래 시간은 예상이고 측정값이 아니다.

## 1. 출발점

해커톤은 빈 저장소가 아니라 이미 동작하는 프로토타입에서 시작한다. 2일 동안 할 일은 "지금 안 되는 것" 표의 네 줄이다.

### 1-2. 지금 안 되는 것

| 안 되는 것 | 코드 근거 | 2일 기능 |
| --- | --- | --- |
| PDF(스캔본 포함)·HWP 업로드가 없다. 긴 계약서에서 필요한 조항만 고르는 단계도 없어 전문을 그대로 프롬프트에 넣는다 | `build_site.py`의 `accept`, `extract.py`의 `contract_block()` | 1 |
| 통지 현황은 시나리오의 통지 시점(`notice_sent_after_hours`)으로 시한을 놓쳤는지만 보여 준다. 남은 시간 카운트다운과 통지 문안 초안이 없다 | `render.js`의 통지 현황 목록 | 2 |
| 배상 노출 순위는 보고서 JSON(`Report.ranking`) 안에만 있다. 다른 시스템이 부를 우선순위 API가 없다. 사람 결정은 브라우저 메모리에만 있고 누가·언제 바꿨는지 남지 않는다 | `server.py`(엔드포인트 3개), `schemas.py`의 `RankRow`, `app.js`의 `state.overrides` | 3 |
| CI가 정답지 채점과 다중 시드 평가를 돌리지 않는다. `run_eval.py extraction`은 점수를 출력만 하고 기준 미달로 실패하지 않는다 | `pages.yml`, `eval/run_eval.py` | 4 |

알려진 제약 두 가지도 출발점에 포함한다.

- 실제 모델 점수는 주입 방어 규칙(`<contract>` 감싸기 포함)을 프롬프트에 넣기 전에 잰 값이다. 현재 프롬프트로는 다시 재지 않았다.
- `claude-code` 모드에 도구 차단 플래그(`--tools ""`, `--strict-mcp-config`)를 넣은 뒤 구조화 출력이 함께 동작하는지는 실제 호출로 확인하지 않았다. 깨지면 정답지로 대체되고 보고서의 `llm_fallbacks`에 드러난다.

## 2. 목표 기능

양식 3번과 같은 목록이다. 기능마다 "최소"(2일 안에 반드시)와 "확장"(시간이 남으면)을 나눴다. 최소를 못 끝내면 양식·README에 "목표"로 남긴다.

| 기능 | 주 담당 | 보조 | 예상 시간(사람·시간) |
| --- | --- | --- | ---: |
| 1. 실제 계약서 형식 대응 | 계약 담당 | 화면 담당 | 10 |
| 2. 조치 보드 확장 | 화면 담당 | 계약 담당 | 8.5 |
| 3. 배차 엔진 연동 형태 정리 | 시뮬레이션 담당 | 화면 담당, 발표 담당 | 10 |
| 4. 평가 루프 | 시뮬레이션 담당 | 계약 담당 | 5.5 |

공통 규칙: 네 기능 모두 계산기(`exposure.py`)와 시뮬레이터(`sim.py`, `engine.js`의 정책 부분)를 바꾸지 않는다. 그래야 6절 정책 비교 숫자와 엔진 대조가 그대로 유지된다. `engine.js`를 건드려야 하면 시뮬레이션 담당이 검토하고 `node scripts/verify_engine.js`를 다시 돌린다.

### 2-1. 실제 계약서 형식 대응

| 작업 | 담당 | 시간 |
| --- | --- | ---: |
| 변환 위치 결정(브라우저 또는 로컬 도우미). 제안: 텍스트 PDF는 브라우저에서 mammoth처럼 고정 버전·SRI로 불러오고, 스캔본 OCR과 HWP는 로컬 도우미 쪽 | 계약 담당 | 0.5 |
| 텍스트 PDF에서 본문 추출, 줄바꿈 정리 | 계약 담당 | 2 |
| 사전 분할: 조항 제목·핵심어(지체상금, 지연, 배상, 불가항력, 천재지변, 통지)로 조항을 골라 프롬프트에 넣고, 인용 검사는 원문 전체 기준으로 유지 | 계약 담당 | 3 |
| 분할 시험: 계약서 8부를 무관한 조항 사이에 끼운 긴 합성 문서로 포함률 측정 | 계약 담당 | 1.5 |
| 스캔본 OCR, HWP(확장) | 계약 담당 | 1 |
| 업로드 화면: 파일 형식 추가, 변환 실패 시 붙여넣기 안내 유지 | 화면 담당 | 2 |

**완료 기준(최소)**

- `contracts/*.md` 8부를 PDF로 바꿔 올리면, 정답지(`contracts/golden/*.yaml`)의 인용 문장이 추출된 텍스트에서 원본 .md와 같은 원문 일치 결과를 낸다. 앞 20자 기준(`citations_verbatim_rate`와 같은 규칙)은 8/8, 엄격 기준(`quote_is_verbatim`, 웹 `app.js`와 같은 규칙)은 원본 기준선과 같은 6/8이다. 엄격 기준에서 미래식품(D)과 청람제약(H)은 정답지 인용이 조항 문구를 줄여 적어 원본 .md에서도 통과하지 못한다.
- 긴 합성 문서 8개에서 사전 분할 결과가 정답지 인용 조항을 모두 포함한다: 8/8. 하나라도 빠지면 그 문서는 전문을 쓴다.
- 기존 txt·md·docx·붙여넣기 경로가 그대로 돈다(브라우저 스모크 통과).

**확장:** 스캔본 PDF 1부와 HWP 1부 시연. 실제 모델로 PDF 8부를 추출해 2회차 정확도 95.3%(101/106) 이상인지 확인(비용 발생, 1회 약 $2).

### 2-2. 조치 보드 확장

| 작업 | 담당 | 시간 |
| --- | --- | ---: |
| "현재 시각"(사건 후 경과 시간) 입력 추가. 웹은 패널 슬라이더, 오프라인 대시보드는 보고서 기준 시각 | 화면 담당 | 2 |
| 통지 현황에 고객별 남은 시간(시한 − 현재, 이미 지남, 통지 완료) 표시 | 화면 담당 | 3 |
| 통지 문안 초안: 고객명, 사건, 조항 번호와 원문 인용, 시한을 넣은 템플릿(결정적). 복사 버튼 | 계약 담당(문안), 화면 담당(버튼) | 1.5 + 2 |

**완료 기준(최소)**

- 태풍 시나리오, 정답지 출처에서 통지 시한이 걸린 고객 4곳(한빛전자 24h, 세움건설 12h, 바로유통 48h, 청람제약 48h)에 남은 시간이 나온다. 시한 정각, 이미 지남, 통지 완료의 경계값 시험이 있다.
- 통지 문안 초안의 조항 번호·인용이 계약서 원문 일치 검사를 앞 20자 기준(`citations_verbatim_rate`와 같은 규칙)으로 통과한다: 통지 시한이 있는 고객 4/4. 엄격 기준(`quote_is_verbatim`)으로는 지금 3/4다. 청람제약(H)의 불가항력 정답지 인용이 "… 다만 …"으로 줄여 적혀 있기 때문이다.
- 문안은 템플릿으로 만들어 LLM 없이 나온다. 오프라인 대시보드와 웹에서 같은 문안이 나온다.
- `pytest` 통과, 엔진 대조 기존 36/36 유지.

**확장:** LLM으로 문안 다듬기(원문 인용은 바꾸지 않음). 문안 인용을 엄격 기준 4/4로 맞추려면 H 정답지의 불가항력 인용을 원문 그대로 고쳐야 한다. 정답지를 고치면 mock 엄격 인용 일치율(지금 0.75)도 바뀌므로 [평가 방법](evaluation.md)의 숫자를 같이 갱신한다.

| 작업 | 담당 | 시간 |
| --- | --- | ---: |

| 로컬 도우미에 엔드포인트 추가. 기존 허용 출처·415·429 규칙을 그대로 적용 | 시뮬레이션 담당 | 3 |
| API 시험: 보고서 순위표와 대조, 보안 규칙 | 시뮬레이션 담당 | 2 |
| 승인 흐름 정의: 사람 결정에 누가·언제·이유를 필수로 남기고 JSON으로 내보낸다 | 발표 담당 | 1 |
| 승인 기록 화면: 이유 없이는 뒤집기 저장 불가, 기록 내보내기 | 화면 담당 | 2 |
| 연동 그림 한 장(기존 TMS가 열 하나를 받는 형태) | 시뮬레이션 담당 | 0.5 |

**완료 기준(최소)**

- 태풍 시나리오 +15.9시간 대기 45건을 API에 넣으면 순위가 보고서 `ranking`의 `exposure_rank`와 45/45 같다. 시험으로 고정한다.
- 목록 밖 출처 403, JSON 아닌 요청 415가 새 엔드포인트에도 적용된다(시험).
- 사람 결정 기록에 고객, 원래 판단, 바꾼 판단, 이유, 시각이 남고 JSON으로 내보내진다.

**확장:** 기록을 로컬 도우미에 저장. 인증은 범위 밖이다(도우미는 루프백 전용).

### 2-4. 평가 루프

| 작업 | 담당 | 시간 |
| --- | --- | ---: |
| `run_eval.py extraction`에 기준치를 넘기는 옵션과 미달 시 종료 코드 추가 | 계약 담당 | 1.5 |
| 다중 시드 30개 결과를 추적 파일 `eval/results/robustness.json`과 비교해 다르면 실패하는 단계 | 시뮬레이션 담당 | 1.5 |
| `pages.yml` verify job에 두 단계 추가(결과는 `out/eval`에 써서 추적 파일을 덮어쓰지 않는다) | 시뮬레이션 담당 | 1 |
| 일부러 깨뜨린 PR로 실패 확인 | 시뮬레이션 담당 | 1.5 |

**완료 기준(최소)**

- PR CI가 저장된 실제 보고서 2종을 채점하고, 현재 값(추출 95.3%, 판단 필드 태풍 100%·항만 적체 93.8%, 최종 적용 여부 8/8·6/8, 인용 원문 일치 100%)보다 낮으면 실패한다.
- PR CI가 시드 30개 × 3종을 돌려 추적 결과(90/90 승, 평균 58.7~69.1%)와 다르면 실패한다.
- 정답지 한 항목을 바꾼 시험 PR에서 CI가 실패하는 것을 한 번 확인하고 그 실행 링크를 남긴다.
- 늘어난 CI 시간을 측정해 기록한다(참고: 게이트 PC에서 다중 시드 평가 6.3초).

**한계(숨기지 않는다):** CI는 실제 모델을 부르지 않는다. 그래서 위 단계는 정답지·채점·시뮬레이터 변경을 막고, 프롬프트·모델 변경으로 인한 정확도 하락은 실제 모델을 다시 돌려야 잡힌다. 양식 3번 4항도 같은 범위(정답지·채점·시뮬레이터 변경은 CI가 막고, 프롬프트·모델 변경은 실제 모델 재측정으로 확인)로 적었다. **확장:** 비밀 키를 쓰는 수동 실행 워크플로(1회 약 $2, 2회차 기준 $2.06)로 실제 모델 재측정과 채점을 묶는다.

## 3. 역할별 시간

4절 시간표에서 코드 동결 전 작업 시간은 1일 차 약 8시간, 2일 차 약 3.5시간(통합 1시간 포함), 합계 약 11.5시간이다. 이 가운데 2일 차 12:00–13:00 통합 1시간은 기능 작업에 쓸 수 없으므로, 기능 작업에 쓸 수 있는 시간은 약 10.5시간이다. 계약·시뮬레이션·화면 담당의 예상 합계는 각각 11시간이라 이미 0.5시간 모자란다. 예를 들어 계약 담당의 1일 차 13:30–16:00(2.5시간) 칸에는 사전 분할 3시간과 포함률 시험 1.5시간이 들어가 있다. 그래서 1일 차 16:00 중간 점검에서 확장부터 버린다. 계약 담당은 확장(OCR·HWP 1시간)을 버리면 10시간이 되지만, 시뮬레이션·화면 담당의 11시간에는 확장이 없어 최소 범위만으로도 넘친다. 이 두 역할의 작업은 첫날 아침 범위 확정 때 줄이거나 다른 역할로 옮긴다.

| 역할 | 맡는 기능 작업 | 합계(예상) | 동결 뒤 |
| --- | --- | ---: | --- |

## 5. 시작 점검, 코드 동결, 그 뒤 할 일

### 5-1. 1일 차 시작 점검

출발점이 1-1절과 같은지 먼저 확인한다. 설치와 Windows·사내망 주의는 [설치·실행 가이드](setup-guide.md)에 있다.

```bash
pytest -q                                   # 71 passed
python -m clausetower demo --llm mock       # 6절 표의 숫자
python scripts/build_site.py && node scripts/verify_engine.js   # 36/36
```

선택: 현재 프롬프트와 도구 차단 플래그로 실제 호출이 되는지 1회 확인한다. 과금되며, 2회차 로그 기준 태풍 시나리오 하나에 호출 16회, $1.78, 70초였다. 보고서의 `llm_fallbacks`가 0이어야 한다. 결과는 `out/` 아래에 쓰여 추적 파일을 바꾸지 않는다.

```bash
python -m clausetower run typhoon --llm claude-code --no-search --out out/check
```

### 5-2. 코드 동결(2일 차 13:00)

- 동결 뒤에는 `src/`, `scripts/`, `prompts/`, `eval/run_eval.py`, `.github/`를 바꾸지 않는다. 데모를 막는 버그만 예외이고, 고치면 게이트를 다시 돌린다.
- 동결 직후 품질 게이트를 처음부터 다시 돌리고, 문서 숫자는 그 결과의 `facts`에서만 가져온다.

```bash
python .claude/skills/ct-quality-gates/scripts/run_gates.py --out _workspace/gates_freeze.json
```

게이트 스크립트를 쓸 수 없는 PC에서는 README 8절 "검증 절차" 명령을 그대로 돌린다.

### 5-3. 동결 뒤 할 일

| 할 일 | 기준 | 담당 |
| --- | --- | --- |
| 게이트 결과 확인 | `summary.ok`가 true, `tracked_files_changed_by_gates`가 비어 있음. 브라우저 스모크는 Playwright가 있는 PC에서 통과 | 시뮬레이션 담당 |
| 바뀌는 숫자 갱신 | 시험 수(지금 71), 엔진 대조 항목 수(지금 36/36, 대조를 더하면 바뀜). 정책 비교·다중 시드 숫자는 바뀌지 않아야 하며, 바뀌면 원인부터 찾는다 | 시뮬레이션 담당 |
| 실제 모델 수치 표기 | 다시 재지 않았으면 "주입 방어 규칙 전 프롬프트로 잰 값"을 유지한다. 사전 분할을 넣었으면 "분할 전 파이프라인으로 잰 값"도 적는다. 다시 쟀으면 3회차로 따로 적고 1·2회차와 섞지 않는다 | 계약 담당 |
| 구현됨·목표 갱신 | 최소 기준을 끝낸 기능은 양식 3번·README 10절에서 "구현됨"으로, 못 끝낸 것은 "목표"로. 두 문서와 이 계획의 목록이 같아야 한다 | 발표 담당 |
| 스크린샷 재촬영 | `node scripts/screenshot.js out/demo/dashboard.html docs/screenshots`, 웹은 `node scripts/smoke_web.js site/index.html docs/screenshots/web`. 웹 조치 보드 스크린샷(`docs/screenshots/web/web_actions.png`)은 지금의 면책 성립 판정을 넣기 전에 찍은 것이라 반드시 다시 찍는다 | 화면 담당 |
| 사이트 재조립 | 문서를 고친 뒤 `python scripts/build_site.py`(사이트의 `docs/` 사본 갱신) | 화면 담당 |

## 6. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| PDF·OCR·HWP 라이브러리를 사내망에서 받지 못한다 | 텍스트 PDF를 기본으로 하고, 실패하면 지금처럼 붙여넣기 안내를 띄운다. 외부 스크립트는 고정 버전과 SRI로 싣는다 |
| OCR 품질이 낮아 인용 원문 일치가 떨어진다 | 스캔본은 확장으로 둔다. 시연은 텍스트 PDF로 한다 |
| 사전 분할이 조항을 빠뜨린다 | 포함률 8/8을 최소 기준으로 두고, 확신이 없으면 전문을 넘긴다 |
| 새 기능이 엔진 대조를 깨뜨린다 | 계산기·정책은 건드리지 않는다. `engine.js`를 바꾸면 시뮬레이션 담당 검토와 `verify_engine.js` 통과가 필수 |
| 실제 모델 호출이 사내망·CLI 문제로 실패한다 | 데모는 mock으로 전부 돈다. 실패는 `llm_fallbacks`·`fallback`으로 드러나므로 숫자를 실제 모델 결과로 쓰기 전에 0인지 확인한다 |
| 세움건설 "시한을 지켰다면 0원" 장면이 웹 기본 출처(실제 Claude 추출)에서 재현되지 않는다 | 이 장면은 정답지 출처로 바꿔 시연한다([데모 대본](demo-script.md)) |
| 시간이 모자란다 | 16:00 중간 점검에서 확장을 버린다. 최소 기준을 못 끝낸 기능은 문서에 "목표"로 남기고 데모에서 빼낸다 |
| 동결 뒤 숫자가 문서와 어긋난다 | 숫자는 동결 직후 게이트 `facts`에서만 옮긴다. 손으로 고친 숫자를 두지 않는다 |
