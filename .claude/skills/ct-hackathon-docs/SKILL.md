# ClauseTower 해커톤 문서

심사위원은 문서를 읽고 세 가지를 판단한다. 문제가 진짜인가, 해법이 AI를 제대로 쓰는가, 주장이 재현되는가. 그래서 이 저장소의 문서는 **모든 숫자를 측정값에서 가져오고, 측정하지 않은 것은 "목표"라고 쓰고, 한계를 먼저 밝힌다.** 이 원칙이 기존 문서의 신뢰를 만든 핵심이므로 새 문서도 그대로 따른다.

## 작성 절차

1. **근거를 모은다.** 게이트 결과 JSON(`_workspace/01_qa_gates.json` 또는 최신 `_workspace/04_qa_gates_r*.json`)의 `facts`를 연다. 어떤 `facts` 키가 어떤 주장을 뒷받침하는지는 `.claude/skills/ct-quality-gates/SKILL.md`의 「결과 JSON 읽는 법」에 있다. 실제 모델의 호출·비용·시간은 `eval/results/real*/run.log`에서 가져온다.
2. **맡은 문서의 명세를 읽는다.** `references/doc-catalog.md`에서 해당 문서 절(목적, 독자, 필수 구성, 근거, 분량)을 읽는다.
3. **기존 문서가 있으면 먼저 읽는다.** 갱신은 틀린 곳·빠진 곳만 고친다. 구조와 문체를 유지한다.
4. **쓴다.** `references/style-guide.md`의 문체·숫자 표기·용어집을 따른다.
5. **스스로 점검한다.** 아래 「자기 점검」을 통과시킨다.
6. **보고한다.** 사용한 근거 경로를 `sources_used`에, 근거를 찾지 못한 주장과 숫자 충돌을 `open_questions`에 남긴다.

## 근거 우선순위

1. 게이트 결과 JSON의 `facts`(지금 다시 잰 값)
2. 추적 중인 측정 파일: `eval/results/robustness.md|json`, `eval/results/extraction_*.json`, `eval/results/real/`, `eval/results/real_prev/`
3. 코드와 설정: `src/clausetower/`, `scripts/`, `pyproject.toml`, `.github/workflows/pages.yml`
4. 기존 문서. 기존 문서끼리 다르면 1~3으로 판정하고, 판정할 수 없으면 `open_questions`에 둔다.

1과 2가 다르면 어느 쪽도 임의로 고르지 않는다. 두 값과 출처를 `open_questions`에 적는다.

## 자기 점검

- [ ] 문서의 모든 숫자에 출처가 있고, 출처의 값과 같다.
- [ ] 1회차·2회차처럼 측정 시점이 다른 숫자를 한 문장에 섞지 않았다. 섞어야 하면 회차를 밝혔다.
- [ ] 판단 필드 정확도(`judgment_accuracy`)와 고객 단위 최종 적용 정확도(`applies_accuracy`)를 같은 이름으로 쓰지 않았다.
- [ ] 명령은 실제로 있는 하위 명령·옵션이다. mock 명령은 실행해 확인했다.
- [ ] 언급한 파일·폴더가 있다. 링크는 상대 경로이며 깨지지 않는다.
- [ ] "구현됨"과 "목표"가 다른 문서와 모순되지 않는다(예: 이미 있는 조치 보드를 2일 과제로 쓰지 않는다).
- [ ] 용어집의 표기를 따랐다. 옛 용어(페널티 노출액 등)가 없다.
- [ ] 가상 데이터, 정답지 작성자, 시뮬레이터 규모, 실제 모델 측정 횟수의 한계를 숨기지 않았다.

## 사실 검증(ct-verifier)

문서 사실 검증은 문서에서 **검증 가능한 주장**을 모두 뽑아 하나씩 대조한다.

| 주장 종류 | 대조 대상 | 문제 등급 |
| --- | --- | --- |
| 숫자(금액, %, 건수, 시험 수, 항목 수, 시간, 비용) | `facts` → 추적 측정 파일 → 코드 | 다르면 `error` |
| 명령·옵션 | `cli.py`의 argparse 정의, 실제 실행(mock만) | 없거나 안 돌면 `error` |
| 파일·경로·링크 | 파일 시스템 | 없으면 `error` |
| 기능 주장("~한다", "~를 지원한다") | 코드 | 코드에 없으면 `error`, 일부만 있으면 `misleading` |
| 지표 해석 | 지표 정의(`eval/run_eval.py`) | 정의와 다르게 읽히면 `misleading` |
| 용어·표기 | `references/style-guide.md` 용어집 | `nit` |

반올림 차이는 문제로 보지 않는다. 문제마다 위치(절 제목 또는 줄), 원문 주장, 무엇이 틀렸는지, 올바른 값과 출처를 적는다. 교차 검토 모드에서는 여러 문서가 같은 사실을 다른 숫자·용어로 말하는 곳과 문서 사이 링크가 깨진 곳을 찾는다.
