## runtime

심사위원과 팀원이 README만 보고 저장소를 받아 돌리는 상황을 따라간다. 한국어 Windows, 사내 프록시, macOS, GitHub Actions(Ubuntu) 네 환경을 떠올린다.

**살펴볼 파일:** `README.md` 8절, `pyproject.toml`, `.github/workflows/pages.yml`, `.gitignore`, `src/clausetower/{cli,contracts,llm,dashboard}.py`, `scripts/*`, `tests/*`, 게이트 결과의 `env`

| 항목 | 확인할 질문 |
| --- | --- |
| 빠른 시작 | README 8절 명령을 순서대로 실행하면 그대로 되는가. Windows 활성화 명령, `/tmp` 같은 POSIX 경로가 섞여 있지 않은가 |
| 설치 방식 | 편집 설치(`pip install -e`)가 아니면 무엇이 깨지는가. `Path(__file__).parents[...]`로 저장소 루트를 찾는 코드, `package-data`에 적힌 경로와 실제 파일 위치가 맞는가 |
| 작업 디렉터리 | 저장소 루트가 아닌 곳에서 CLI를 실행하면 되는가(`eval` 하위 명령의 import 등) |
| 의존성 | `pyproject.toml`의 의존성 범위가 실제 사용 API(예: SDK의 구조화 출력 메서드)를 보장하는가. 시험·스크립트가 쓰는 도구(Node, Playwright)가 문서·설정에 드러나 있는가 |
| Python 버전 | `requires-python`과 CI 버전, 최신 버전(3.13~3.14)에서 경고·오류가 없는가 |
| 콘솔 인코딩 | cp949 콘솔·파이프 출력에서 CLI와 스크립트가 깨지거나 실패하지 않는가 |
| 사내 프록시 | `HTTP(S)_PROXY`가 있고 `NO_PROXY`에 127.0.0.1이 없을 때 로컬 서버 시험과 로컬 도우미 연결이 되는가 |
| 시험 독립성 | 시험이 설치 상태, 네트워크, 이전 실행 산출물(`out/`, `site/`)에 기대는가. 순서를 바꾸거나 일부만 돌려도 되는가 |
| 결정성 | 같은 명령을 두 번 돌리면 같은 숫자가 나오는가. 난수·시각·딕셔너리 순서에 기대는 곳이 있는가 |
| CI 워크플로 | 시험 → 조립 → 검증 → 배포 순서가 맞는가. 실패 시 배포가 막히는가. 액션 버전 고정, 권한 범위(`contents: write`), 동시 실행 제어, 캐시, 브라우저 스모크 포함 여부 |
| 배포 산출물 | `site/`에 들어가는 파일(README·문서·스크린샷 복사 포함)이 의도한 것뿐인가. 기본 브랜치·Pages 설정과 README 링크가 맞는가 |
| 오프라인 데모 | 네트워크 없이 `demo --llm mock`과 `dashboard.html`이 끝까지 되는가. 웹 데모가 외부 CDN(글꼴, mammoth)에 기대는 정도 |

## security

계약서는 실제 적용 시 민감 문서다. 해커톤 데모라도 "계약서 본문은 선택한 LLM 외에는 어디에도 전송되지 않는다"는 주장이 사실인지, 로컬 도우미가 열어 두는 범위가 어디까지인지 확인한다.

**살펴볼 파일:** `src/clausetower/server.py`, `src/clausetower/llm.py`, `src/clausetower/extract.py`, `src/clausetower/web/app.js`, `scripts/build_site.py`(HTML 템플릿), `prompts/*.md`, `tests/test_server_and_openai.py`

| 항목 | 확인할 질문 |
| --- | --- |
| 로컬 도우미 CORS | 허용 출처를 어떻게 정하는가. 요청 `Origin`을 그대로 반사하는가. Private Network Access 허용과 결합되면 아무 웹사이트가 사용자의 PC에서 LLM 호출(구독·사내 토큰 사용)을 시킬 수 있는가 |
| 바인딩과 노출 | 기본 바인딩 주소, `--host 0.0.0.0` 같은 옵션의 경고, 인증 유무, 요청 크기·속도 제한 |
| 오류 응답 | 500 응답이나 로그에 계약 본문·키·내부 경로가 섞이는가 |
| 키 보관 | 브라우저 `localStorage`에 키를 두는 방식과 그 사실의 고지. 직접 브라우저 호출에 필요한 헤더와 그 위험 고지 |
| 외부 스크립트 | CDN 스크립트(예: mammoth)의 버전 고정과 무결성(SRI) 속성 |
| 데이터 흐름 주장 | "선택한 LLM 엔드포인트 외에는 전송하지 않는다"가 코드상 사실인가(글꼴 등 다른 외부 요청, 로그) |
| LLM 실패 처리 | 실제 모드에서 호출이 실패해 mock(정답지)으로 대체되면 화면·보고서에 그 사실이 드러나는가. 조용히 정답지 숫자를 "실제 모델" 결과처럼 보이게 하는 경로가 있는가 |
| CLI 하위 프로세스 | Claude Code CLI 호출의 도구 차단 목록, 작업 디렉터리 격리, 시간 제한, 시스템 프롬프트·스키마 전달 방식 |
| 프롬프트 주입 | 업로드 계약서 본문 안의 지시문이 추출·판단을 조작할 여지와, 인용 원문 일치 검사·조건의 기계적 결합이 그 피해를 어디까지 막는가 |
| 비밀값 | 저장소·`site/`·스크린샷·실행 로그에 키, 사내 주소, 개인 정보가 들어 있지 않은가 |

## engine

"같은 화물·같은 교란에서 순서만 바꿔 58~77% 절감"과 "웹 엔진이 파이썬과 같다"는 주장이 출품작의 핵심 증거다. 이 증거가 얼마나 단단한지 본다.

**살펴볼 파일:** `src/clausetower/{exposure,sim,agent,schemas}.py`, `src/clausetower/web/engine.js`, `scripts/verify_engine.js`, `tests/test_exposure.py`, `tests/test_sim_and_agent.py`, `contracts/golden/*.yaml`, `scenarios/*.yaml`

| 항목 | 확인할 질문 |
| --- | --- |
| 계산 순서 | 유예 → 단위 올림 → 요율·누진·정액 → 건별 상한 → 고객 합계 상한 순서가 README 5-3절과 코드에서 같은가 |
| 경계값 | 유예와 정확히 같은 지연, 0 지연, 영업일 계산의 주말 경계, 누진 구간 경계, 상한 도달 직후, 가중 정액(24h 초과) |
| 면책 결합 | `applies`를 조건 결합으로 다시 만드는 곳이 파이썬(`extract.py`)과 JS(`deriveJudgment`)에서 같은 규칙인가. `conditions_met`가 비었을 때의 처리 |
| 엔진 대조 범위 | `verify_engine.js`가 무엇을 대조하는가(총액·순위·시드 A만?). 웹 데모가 쓰는 다른 시드·조작 패널 경로가 대조 밖에 있는가 |
| 결정성 | 탐색 근사 최적 등 난수를 쓰는 곳의 시드 고정. 같은 입력의 반복 실행 결과 |
| 정책 공정성 | 정책 사이에 "다음 화물 선택 규칙" 외의 차이가 없는가(결항·노선 지연·상한 적용이 같은가) |
| 시험 공백 | 위 경계값과 면책 결합, JS 쪽 계산에 시험이 있는가. 시험 이름과 실제 단언이 맞는가 |
| 숫자 재현 | 게이트의 `scenarios_mock`, `robustness`, `engine_parity`가 추적 파일(`eval/results/`)과 같은가 |

## docs

문서는 두 가지를 본다. (1) **정확성:** 적힌 숫자·명령·경로·기능이 지금 저장소와 맞는가. (2) **완결성:** 해커톤 심사·발표·당일 작업에 필요한 문서가 있는가. 문서 목록과 각 문서의 요구 구성은 `.claude/skills/ct-hackathon-docs/references/doc-catalog.md`, 용어는 같은 폴더의 `style-guide.md`를 기준으로 한다.

**살펴볼 파일:** `README.md`, `docs/*.md`, `pyproject.toml`의 설명 문구, `src/clausetower/cli.py` 도움말, 웹 HTML 문구(`scripts/build_site.py`), 게이트 결과의 `facts`

| 항목 | 확인할 질문 |
| --- | --- |
| 숫자 | 각 문서의 금액·절감률·승률·정확도·시험 수·검증 항목 수가 `facts`와 같은가. 1회차·2회차처럼 측정 시점이 다른 숫자를 섞어 쓰지 않았는가 |
| 지표 정의 | 판단 "필드 정확도"와 고객 단위 "최종 적용 여부 정확도"처럼 정의가 다른 지표를 구분해 쓰는가 |
| 명령·경로 | 문서의 명령이 실제로 있고 그대로 도는가. 언급한 파일이 있는가. LLM 모드 목록(`openai` 포함)이 코드와 같은가 |
| 문서 간 일관성 | README·기획서·양식 답안·데모 대본이 같은 사실을 같은 숫자로 말하는가. "이미 구현됨"과 "2일 동안 구현할 것"이 서로 모순되지 않는가 |
| 용어 | 최근 통일한 용어(배상 노출액, 배상 노출 순, 배상금)를 쓰는가. 옛 용어(페널티 노출액 등)가 문서·패키지 설명·화면에 남았는가 |
| 측정과 목표 | 측정하지 않은 효과를 측정값처럼 쓰지 않았는가 |
| 한계 공개 | 가상 데이터, 정답지 작성자, 작은 시뮬레이터, 실제 모델 측정 횟수 같은 한계를 숨기지 않는가 |
| 해커톤 완결성 | 문서 목록의 문서 가운데 빠진 것: 설치·실행 가이드(Windows·사내망 포함), 아키텍처, 평가 방법, 심사 예상 질문, 2일 구현 계획. 빠진 문서마다 `doc-gap` 지적 하나 |
| 첫 화면 | 저장소 기본 브랜치에서 README와 문서 링크·이미지가 깨지지 않는가 |
