# ClauseTower 3분 데모 대본

발표자가 리허설과 발표 직전에 읽는 대본이다. 숫자는 mock 데모 실행값(정답지 출처, `python -m clausetower demo --llm mock`)과 실제 모델 2회차 보고서(`eval/results/real/`)에서 가져왔고, 기준은 [README 6절](../README.md)과 같다. 설치는 [setup-guide.md](setup-guide.md), 길게 받는 질문은 [judge-qa.md](judge-qa.md)에 있다.

## 1. 준비

**1차: 오프라인 대시보드(네트워크·비용 없음).** 발표는 이 두 탭으로 끝낸다.

```bash
python -m clausetower demo --llm mock                                       # 탭 1: out/demo/dashboard.html (정답지, 시나리오 3종)
python -m clausetower demo --from-reports eval/results/real --out out/real  # 탭 2: out/real/dashboard.html (저장된 실제 모델 보고서, LLM 호출 없음)
```

- 탭 1은 태풍 탭을 맨 위로 올려 둔다. 탭 2는 실제 Claude(claude-opus-5-5)가 계약서 8부를 읽은 2회차 보고서로 그린 화면이다(태풍·항만 적체 2종).
- `scripts/real_run.py`는 새로 측정할 때만 쓴다. `claude` CLI(또는 API 키)가 필요하고 실행당 약 $2가 든다(2회차 24회 호출, $2.06, 호출 시간 합계 283초(병렬 4개로 실제 소요 약 101초), `eval/results/real/run.log`). 대시보드는 만들지 않고 `out/real/<시나리오>/report.json`만 쓴다. 리허설에서 돌리지 않는다.
- 설치가 안 된 PC(한국어 Windows·사내망 포함)는 [setup-guide.md](setup-guide.md)를 먼저 따른다.

**선택: 웹 데모(https://namojo.github.io/clausetower/).** 네트워크가 필요하다. 질의응답에서 "조건을 바꾸면?"이 나올 때 연다.

- 왼쪽 패널의 통지 시점·사실 스위치·트럭 수를 바꾸면 전체가 다시 계산된다.
- 웹의 기본 계약 읽기 출처는 실제 Claude 추출이다. 조치 보드의 "통지 12h로 시뮬레이션" 버튼으로 세움건설을 0원으로 만드는 장면은 출처를 **정답지**로 바꿔야 나온다(아래 출처 주의).
- 사이트가 막히면 로컬로 조립해 연다. `python scripts/build_site.py` 뒤 `python -m http.server 8000 --directory site`로 띄우고 `http://localhost:8000/`을 연다.
- 라이브 AI(계약서 업로드)는 과금되고 추출에 22초쯤 걸린다(README 3-8절의 구독 경로 실측). 쓰려면 `python -m clausetower serve --llm codex`(Codex CLI)를 띄우고 웹 화면에서 도우미 연결을 확인해 둔다. 발표 시간 안에서는 쓰지 않는다.

**출처 주의.** 태풍의 총 배상금은 두 출처가 같다(12,834,000원 → 2,996,500원). 다만 실제 모델은 세움건설 면책에 통지 외 조건까지 적어서, 실제 모델 출처(탭 2, 웹 기본)에서는 조치 보드가 "통지 외 조건 … 미충족이라 통지만으로는 면책 안 됨"을 보이고 면책으로 570,000원이 0원이 된다고 약속하지 않는다. **"시한을 지켰다면 0원"은 정답지 출처(탭 1, 웹에서 정답지 선택)에서만 말한다.**

## 3. 실패 대비

| 증상 | 대체 화면·조치 |
| --- | --- |
| 네트워크 없음, 사내망이 외부 사이트를 막음 | 탭 1·2(오프라인 대시보드)만으로 진행한다. 둘 다 외부 자원을 쓰지 않는다. 웹 데모는 건너뛴다 |
| 웹 데모가 안 열림 | 로컬 조립본(`http://localhost:8000/`)을 연다. 그것도 안 되면 `docs/screenshots/web/`의 스크린샷(`web_overview.png`)을 보여 준다. `web_actions.png`는 수정 전 화면이라 쓰지 않는다(실제 모델 출처인데도 세움건설 570,000원 면책 약속과 통지 버튼이 보이지만, 지금 화면은 면책 금액을 약속하지 않는다) |
| 프로젝터 해상도가 낮아 글자가 작거나 표가 넘침 | 브라우저 확대(Ctrl +)로 맞추고 리허설 때 프로젝터에서 미리 확인한다. 스크린샷(`docs/screenshots/`)은 1280×900 화면 기준으로 찍었다(`scripts/screenshot.js`) |
| 로컬 도우미 연결 실패("도우미에 연결할 수 없다") | `serve`가 떠 있는지, 주소가 `http://127.0.0.1:8787`인지 확인한다. 페이지를 파일로 열면 출처가 `null`이라 403이 난다. `http://localhost`로 띄우거나 배포 사이트를 쓴다. 다른 출처는 `--allow-origin`이나 `CLAUSETOWER_ALLOWED_ORIGINS`로 더한다. 동시 요청이 많으면 429가 나므로 한 건씩 보낸다 |
| 라이브 AI가 느리거나 실패(대체 표시, `fallback`) | 업로드 시연을 접고 탭 2(저장된 실제 모델 결과)와 `docs/screenshots/web/web_live_helper_real.png`로 대신한다 |
| 대시보드 명령이 `No module named clausetower`로 실패 | `pip install -e .` 또는 `PYTHONPATH=src`. 자세한 해결은 [setup-guide.md](setup-guide.md)의 문제 해결 표 |
| 탭 2에서 세움건설 0원 장면이 안 나옴 | 정상이다. 실제 모델 출처에서는 통지만으로 면책이 안 된다. 탭 1(정답지)로 돌아가 보여 준다 |

## 4. 예상 질문

- **계약 해석을 AI가 하면 책임은?** 최종 결정은 사람이다. 도구는 조항 원문과 노출액을 보여 주는 참모다. 면책 적용은 조건을 기계적으로 결합해 확정한다.
- **실제 효과는?** 이 모형에서 순서만 바꿔 58~77%. 시드 30개 × 시나리오 3종에서 90/90 개선(평균 58.7~69.1%). 실제 네트워크 수치는 TMS 데이터로 다시 재야 한다.
- **기존 TMS와 차이는?** SLA 마감 긴급도 배차는 있다. 조항 구조(상한, 유예, 불가항력 조건, 통지 시한)를 읽어 실제 노출액으로 바꾸고 그것으로 배차하는 것은 조사에서 찾지 못했다(README의 선행 조사).
- **LLM이 틀리면?** 2회차에서 항만 적체 2건(누리에너지·세움건설)을 보수적으로 틀렸다(면책을 보류, 1회차는 누리에너지 1건). 그 이유가 카드에 적혀 나와 사람이 확인한다. 이 측정은 프롬프트에 주입 방어 규칙을 넣기 전에 잰 값이다.
- **정답지를 팀이 썼으면 자기 채점 아닌가?** 맞다. 그래서 mock 모드의 추출 100%는 의미가 없고, 실제 모델 점수만 본다. 계약서 8부와 사건 3종은 모두 가상이다.

더 많은 질문(심사 기준 4개별)과 근거 경로는 [judge-qa.md](judge-qa.md), 지표 정의와 재현 명령은 [evaluation.md](evaluation.md)에 있다.
